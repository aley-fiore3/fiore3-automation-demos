## What These Stories Are

These aren't sanitized project summaries. They're engagement narratives written the way I'd walk through a problem with a technical hiring manager: what the client thought the problem was, what I found when I actually looked, what I chose not to automate and why, and what I left behind so the client could own it.

The through-line in every case is judgment — knowing when a spreadsheet formula is the right call and when it isn't, when to build a robust pipeline and when that's overkill, when to say no to a feature that would create more risk than value.

---

## Format

Every case study includes:

- **Header block** — industry, problem type, time to build, outcome
- **Background** — what the client was doing and where the pain was
- **What I Found When I Embedded** — what observation revealed that wasn't obvious from the outside
- **What I Built** — technical description with code snippets where relevant
- **Results** — before/after table with measurable metrics
- **What I Left Behind** — handoff docs, runbooks, and config files so the client owns it
